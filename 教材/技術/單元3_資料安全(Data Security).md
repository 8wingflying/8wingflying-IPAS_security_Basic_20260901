# 資料安全(Data Security)

## 1. 資料安全（Data Security）核心概念
- 資料安全旨在確保數位資產在全生命週期（創建、傳輸、儲存、使用、共享、歸檔、銷毀）中，免受非授權存取、外洩、竄改、破壞或勒索威脅。
- 其核心立足於資訊安全的三大要素（**CIA Triad**），並延伸至隱私法規遵循（如 GDPR、個人資料保護法、HIPAA、ISO 27001 等）：

* **機密性（Confidentiality）**：確保僅有具備合法授權的主體（使用者、系統、服務）方可存取機敏資料。
* **完整性（Integrity）**：保證資料在儲存與傳輸過程中保持準確、真實且未遭非授權竄改或毀損。
* **可用性（Availability）**：確保授權主體在業務需要時，能穩定、及時地存取所需之資料。

## 資料狀態與安全關鍵技術

根據資料在系統環境中的不同狀態與防禦面向，對應的防護技術及實作方式：

| 保護面向 / 狀態 | 防禦重點與目標 | 核心關鍵技術 | 技術機制與實作說明 |
| :--- | :--- | :--- | :--- |
| **傳輸中安全**<br>*(Data in Transit)* | 防止資料在通訊網路中遭到竊聽、中間人攻擊（MITM）與資料竄改 | **TLS 1.3 / mTLS**<br>**IPsec / WireGuard VPN**<br>**SSHv2 / SFTP** | • 透過非對稱加密交換密鑰，並採用高效對稱加密（如 AES-GCM、ChaCha20-Poly1305）傳輸內容。<br>• **mTLS** 實現客戶端與伺服器雙向憑證認證。<br>• 部署 HSTS、憑證綁定（Certificate Pinning）強化防護。 |
| **靜態儲存安全**<br>*(Data at Rest)* | 防止硬體設備遭竊、儲存媒體遺失、資料庫遭未授權導出或外部拖庫 | **AES-256 / XTS-AES**<br>**TDE (透明資料加密)**<br>**KMS / HSM**<br>**信封加密 (Envelope Encryption)** | • 作業系統/磁碟層級全盤加密（BitLocker, LUKS）。<br>• 資料庫原生透明資料加密（如 Oracle TDE, MS SQL TDE）。<br>• 金鑰管理系統（KMS）配合硬體安全模組（HSM, FIPS 140-2/3 Level 3+）確保根金鑰（Master Key）物理隔離。 |
| **使用中安全**<br>*(Data in Use)* | 防止資料在 CPU 運算與主記憶體處理期間，遭受記憶體傾印（Memory Dump）、側信道攻擊或惡意特權代碼窺探 | **TEE 機密運算**<br>*(Intel SGX / AMD SEV)*<br>**同態加密 (FHE/PHE)**<br>**安全多方計算 (SMPC)** | • **TEE (可信執行環境)**：在硬體層劃分隔離飛地（Enclave），即便 Hypervisor 或 OS 遭滲透亦無法讀取內部記憶體。<br>• **同態加密**：允許在密文狀態下直接運算，無需解密即可得出密文結果。 |

## 延伸主題

| 保護面向 / 狀態 | 防禦重點與目標 | 核心關鍵技術 | 技術機制與實作說明 |
| :--- | :--- | :--- | :--- |
| **外洩與擴散防護**<br>*(Exfiltration Defense)* | 主動識別、監控並阻斷機敏資料（個人資料 PII、財務、智慧財產權）向外部管道非授權流出 | **DLP (端點 / 網路)**<br>**CASB (雲端存取代理)**<br>**數位浮水印 (Watermarking)** | • 透過正則表達式、字典、文件指紋（EDM）實施深層封包檢驗（DPI）。<br>• 監控剪貼簿、USB、郵件附件與雲端上傳行為。<br>• 在檔案中嵌入不可逆/盲水印，以利洩漏事後溯源追蹤。 |
| **隱私與去識別化**<br>*(Privacy & Governance)* | 在數據分析、測試環境開發或 AI/ML 模型訓練時，消除個資關聯性以符合法規 | **資料遮罩 (Masking)**<br>**Tokenization (權杖化)**<br>**差分隱私 (Differential Privacy)**<br>**假名化 / 匿名化** | • **靜態/動態遮罩**：依據存取權限即時混淆機敏欄位（如身分證、信用卡號）。<br>• **Tokenization**：使用隨機產生的無意義 Token 取代真實數據，僅集中維護對應表。<br>• **差分隱私**：在查詢結果中注入精準控制的數學雜訊，防止差分攻擊還原個資。 |
| **存取控制與零信任**<br>*(Access Control)* | 落實最小權限原則，動態驗證主體身分、設備健康度與情境環境 | **RBAC / ABAC**<br>**PBAC (基於策略的控制)**<br>**零信任架構 (ZTA)** | • **RBAC**：基於角色分派權限。<br>• **ABAC**：結合使用者屬性、資源分類、環境變數（時間、地點、IP）進行細粒度動態授權。<br>• 消除網路隱含信任（Never Trust, Always Verify）。 |
| **完整性與韌性還原**<br>*(Integrity & Resilience)* | 防範勒索軟體破壞、惡意竄改，並在災難或安全事件發生時快速復原 | **不可竄改儲存 (WORM / Object Lock)**<br>**不可逆雜湊 (SHA-256 / SHA-3)**<br>**隔離備份 (Air-Gapped Backup)** | • **WORM (Write Once, Read Many)**：備份資料在設定保留期內無法被修改或刪除，防範勒索軟體。<br>• 實施 3-2-1-1-0 備份架構（含 1 份離線/不可變備份）。<br>• HMAC 與數位簽章保證傳輸內容未遭偽造。 |
