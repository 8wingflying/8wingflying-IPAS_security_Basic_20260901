# 串流協定 (Streaming Protocols) 

- 影音串流與即時通訊協定依賴不同的底層傳輸機制來平衡低延遲與資料完整性
- 底下為現代網路環境與安控系統中常見的標準及其資安特性：

| 協定名稱 | 核心功能與傳輸特性 | 資安與通訊特徵 |
| :--- | :--- | :--- |
| **HLS** (HTTP Live Streaming) | 由 Apple 開發，基於 HTTP 的自適應位元速率 (ABR) 串流協定。將影音切割為多個短暫的小檔案（如 `.ts`），適合大規模點播與直播。 | 透過標準 HTTP/HTTPS 傳輸（Port 80/443），極易穿透防火牆。支援 AES-128 內容加密與 DRM 機制，防止未授權側錄與盜版。 |
| **MPEG-DASH** (Dynamic Adaptive Streaming over HTTP) | 類似 HLS 的國際開源標準，同樣基於 HTTP 與 ABR 技術。支援多種編碼格式與 DRM 系統，為多數大型影音平台底層架構。 | 依賴底層 HTTPS 提供傳輸層加密，並結合通用加密 (CENC) 保護媒體內容。因採標準 HTTP 請求，傳統網頁應用程式防火牆 (WAF) 即可進行流量監控。 |
| **WebRTC** (Web Real-Time Communication) | 專為瀏覽器與行動裝置設計的點對點 (P2P) 即時通訊技術，底層多基於 UDP 傳輸，能達成極低的延遲（<500 毫秒）。 | 強制要求加密通訊，所有媒體資料皆必須透過 SRTP 傳輸，並使用 DTLS 進行金鑰交換，是目前安全性與隱私保護等級最高的即時通訊標準之一。 |
| **RTMP** (Real-Time Messaging Protocol) | 早期由 Adobe 開發的低延遲直播推流標準，基於 TCP（Port 1935）。現今多用於直播源將訊號推送至伺服器（Ingest），再轉換為 HLS/DASH 派發。 | 傳統 RTMP 採明文傳輸，容易遭中間人攔截或篡改串流內容。目前實務上必須改用 RTMPS（結合 TLS 加密）以確保推流憑證與資料的安全。 |
| **RTSP** (Real Time Streaming Protocol) | 負責建立與控制媒體串流會話（Port 554），常與 RTP/RTCP 搭配負責影音傳輸，廣泛應用於 IP 攝影機 (CCTV) 與物聯網安控系統。 | 預設無內建加密且常缺乏強健的身分驗證機制。若未封閉於內網或搭配 VPN，極易成為 IoT 弱點掃描與未授權監聽的目標。 |
| **RTP/RTCP** (Real-time Transport Protocol) | RTP 負責實際傳載即時影音資料；RTCP 則負責監控服務品質 (QoS) 與傳送統計資訊，為 SIP 或 RTSP 的底層傳輸骨幹。 | 標準 RTP 無安全防護機制，實務上需升級為 SRTP (Secure RTP)，透過 AES 加密確保串流資料的機密性與防重放 (Anti-replay) 攻擊。 |
